# 26.2 API 对照与编译验证记录

本项目的全部 API 调用点都经过**双重核对**：
Fabric/Minecraft 官方文档 + **真实 `./gradlew build` 编译**（2026-xx，Loom 1.18.2 / Gradle 9.7.1 / JDK 25）。

## 一、真实编译暴露出来的 26.2 变化（最重要）

### 1. 输入事件全部改成「事件对象」

这是 26.2 影响最大的一处重构：`Screen` / `AbstractWidget` 的鼠标键盘回调**不再是基本类型参数**，
而是 `net.minecraft.client.input` 包下的事件对象。

```java
// net.minecraft.client.gui.components.events.ContainerEventHandler (26.2 实际签名)
boolean mouseClicked(net.minecraft.client.input.MouseButtonEvent event, boolean doubleClick);
boolean mouseReleased(net.minecraft.client.input.MouseButtonEvent event);
boolean mouseDragged(net.minecraft.client.input.MouseButtonEvent event, double dragX, double dragY);
boolean mouseScrolled(double x, double y, double scrollX, double scrollY);   // ← 这个没变
boolean keyPressed(net.minecraft.client.input.KeyEvent event);
boolean keyReleased(net.minecraft.client.input.KeyEvent event);
boolean charTyped(net.minecraft.client.input.CharacterEvent event);
```

事件对象的访问器：

| 事件类 | 访问器 |
| :--- | :--- |
| `MouseButtonEvent` | `x()`, `y()` (double)，`button()` (int)，`buttonInfo()`, `modifiers()` |
| `KeyEvent` | `key()`, `scancode()`, `modifiers()` (全 int) |
| `CharacterEvent` | `codepoint()` (int), `codepointAsString()`, `isAllowedChatCharacter()` |

> 旧写法 `mouseClicked(double,double,int)` / `keyPressed(int,int,int)` / `charTyped(char,int)`
> 在 26.2 **不再覆盖任何方法**，会报 `方法不会覆盖或实现超类型的方法`。
> 这正是本项目第一次真实编译时唯一的 15 个错误来源。

### 2. `Screen` 没有 `close()` 了，只有 `onClose()`

```
javap net.minecraft.client.gui.screens.Screen →  public void onClose();   // 没有 close()
```

所以「关闭按钮」用 `this::onClose`，别用 `this::close`。

### 3. 其它已核对无误的（26.2 与旧版不同处）

| 旧写法 | 26.2 正确写法 |
| :--- | :--- |
| `PayloadTypeRegistry.playC2S()/playS2C()` | `serverboundPlay()` / `clientboundPlay()` |
| `ResourceLocation` | `net.minecraft.resources.Identifier` |
| `Minecraft#setScreen` / `#screen` | `Minecraft#gui` → `Gui#setScreen` / `Gui#screen()` |
| `Screen#render(GuiGraphics, …)` | `Screen#extractRenderState(GuiGraphicsExtractor, int, int, float)` |
| `GuiGraphics#drawString` | `GuiGraphicsExtractor#text(Font, String\|Component, x, y, argb, shadow)` |
| `KeyBindingHelper`(`...client.keybinding.v1`) | `KeyMappingHelper`(`...client.keymapping.v1`) |
| `new KeyMapping(name, type, code, "category")` | `new KeyMapping(name, type, code, KeyMapping.Category.MISC)` |
| 控件 `renderWidget(...)` | `AbstractWidget#extractWidgetRenderState(GuiGraphicsExtractor, …)` |

## 二、构建记录

```powershell
$env:JAVA_HOME = 'D:\Program Files\java'   # JDK 25
.\gradlew.bat build
```

- 首次构建：Loom 1.18.2 拉取 MC 26.2 / Fabric API 0.161.0+26.2，`compileJava` 报 15 个错误（全部是上面的输入事件 + `close()`）。
- 修正后：**BUILD SUCCESSFUL**，产物 `build/libs/mapdrawclient-1.0.0.jar`（91 KB）+ `-sources.jar`（53 KB）。
- jar 内已包含 `fabric.mod.json`、`assets/mapdrawclient/**`（图标/语言/贴图）与全部 class。

本机用了两个国内加速点（只在本地构建环境，不影响项目本身）：

- `gradle/wrapper/gradle-wrapper.properties` → Gradle 发行包换成腾讯镜像
  （`services.gradle.org` 直连会 10 秒超时；镜像地址 `https://mirrors.cloud.tencent.com/gradle/gradle-9.7.1-bin.zip`）
- `GRADLE_USER_HOME` 本机指向 `D:\gradle-cache`，缓存体积约 1 GB。

> 如果你在别的机器上构建，把 wrapper 的 `distributionUrl` 改回官方地址即可。

## 三、协议层最容易踩的坑

1. **UTF 编码**：服务端 `DataInputStream.readUTF()` 是 2 字节长度前缀，MC 的 `FriendlyByteBuf#writeUtf` 是 VarInt 前缀。
   本项目一律用 `DataOutputStream` 拼包（`MapDrawClientNetworking#build`），**不要**改成 `writeUtf`。
2. **`0x80` / `0x81` 要按无符号读**：`readUnsignedByte()`，否则 `0x81` 会被当成 `-127`。
3. **一个通道只能有一个 payload 类型**：`mapdraw:main` 的所有包共用 `MapDrawPayload`，靠首字节区分，
   这样才能和 Paper 的 `sendPluginMessage` 完全互通。
4. **`0x81` 包大小**：16384 字节像素 + 元数据 ≈ 16.5 KB，小于原版自定义负载上限 32767，普通 `register` 足够；
   若以后协议超过 32 KB，改用 `PayloadTypeRegistry.clientboundPlay().registerLarge(TYPE, CODEC, maxSize)`。
